    系统管理

    系统管理用于维护平台账号、权限、运行日志、存储空间和平台版本。该模块包含管理级操作，建议由平台管理员使用。

    进入系统管理

    1. 登录 AI Studio。
    2. 在左侧导航栏选择 系统管理。
    3. 默认打开系统总览，也可以通过页面视图切换到用户、角色、日志、存储或更新页面。

    系统管理相关地址如下：

    功能 地址 适用角色
    系统总览 /system?view=overview 管理员
    用户管理 /system?view=users 管理员，需具备用户查看权限
    角色与权限 /system?view=roles 管理员，需具备权限管理权限
    日志管理 /system?view=logs 管理员
    存储管理 /system?view=storage 管理员，需具备存储查看权限
    平台更新 /system?view=updates 用户和管理员

    系统总览

    系统总览用于快速查看平台当前运行状态。进入页面后，先确认页面没有错误提示，再根据状态信息判断是否需要进一步检查用户、日志或存储。

    建议按照以下顺序检查：

    1. 查看平台整体状态和版本信息。
    2. 检查最近的异常或告警。
    3. 如果页面提示资源不足，转到 存储管理 查看空间使用情况。
    4. 如果出现访问或操作异常，转到 日志管理 查询对应时间段的记录。

    总览页的日常检查

    建议管理员每天首次登录后完成一次快速检查：

    1. 确认页面顶部没有网络、服务不可用或权限不足提示。
    2. 记录当前平台版本；升级或故障报修时需要提供该版本号。
    3. 查看运行状态、任务状态和资源使用率。出现异常时，先记录时间和页面提示，再进入日志管理。
    4. 点击刷新按钮重新获取状态。刷新后仍异常，才按故障流程继续排查。

    总览页显示的是当前时刻的状态，涉及任务数量、存储空间或服务状态的判断，应以刷新后的数据为准。

    用户管理

    用户管理用于查看和维护平台账号。处理账号问题时，应先确认用户名、所属角色和账号状态，再执行修改或停用操作。

    建议：

    • 每个账号只授予完成工作所需的最小权限。
    • 离职、转岗或长期不使用的账号应及时停用。
    • 不要多人共用管理员账号，避免日志无法追溯到具体操作者。
    • 修改权限后，让用户重新登录以确认权限已生效。

    新增或维护账号

    1. 打开 用户管理，按用户名或账号标识查找用户。
    2. 新增账号时填写可识别的用户名，并分配业务所需的角色；不要使用多人共用账号。
    3. 修改账号前核对账号状态和当前角色。停用账号前确认没有正在运行的任务归属该账号。
    4. 保存后重新打开账号详情，确认状态、角色和更新时间已生效。

    角色与权限

    角色用于集中分配功能权限。新增或调整角色时，先明确业务范围，再逐项勾选权限；不要直接复制管理员角色给普通用户。

    权限调整完成后，建议用目标账号验证以下内容：

    1. 可以看到的菜单是否符合预期。
    2. 只读用户是否无法执行新增、修改或删除操作。
    3. 无权限访问页面时，平台是否正确提示权限不足。

    权限遵循“按需授权”原则。查看权限只允许读取数据，编辑权限允许新增或修改，删除和系统配置权限应仅授予明确负责该业务的管理员。

    日志管理

    日志管理用于定位登录失败、权限变更、配置修改和平台异常。排查问题时建议记录：发生时间、操作者、功能页面、操作类型和错误信息。

    查询日志的建议流程：

    1. 先按问题发生时间缩小范围。
    2. 再按用户或操作类型筛选。
    3. 打开具体记录，核对请求结果和失败原因。
    4. 将关键日志编号或截图附到故障记录中。

    日志可能包含用户名、IP 地址或业务数据，不应直接公开或发送到非授权渠道。

    排查完成后应保留发生时间（含时区）、账号、页面地址、操作步骤、错误提示和日志编号。涉及隐私的数据在对外提交前应脱敏。

    存储管理

    存储管理用于查看平台文件、图片、模型或数据集占用情况。空间接近上限时，优先清理确认不再使用的临时文件和历史产物；删除前应确认没有任务、模型或知识库引用这些文件。

    清理完成后重新刷新页面，确认已用空间和可用空间均已更新。不要直接在服务器文件系统中删除平台目录，以免产生数据库记录与实际文件不一致。

    当可用空间接近上限时，先暂停大文件上传、模型训练或批量导入，再按“临时文件—失败任务产物—确认无引用的历史版本”的顺序清理。正在使用的模型、数据集和知识库文件不可删除。

    平台更新

    平台更新用于查看当前版本及可用更新。执行更新前应完成以下准备：

    • 确认当前没有正在运行的识别、训练或数据处理任务。
    • 备份重要配置和业务数据。
    • 记录当前版本号，便于更新后回退或排查。
    • 选择业务低峰期执行，并提前通知使用人员。

    更新完成后，重新登录并检查系统总览、设备与资产、识别和 API 管理等核心页面。

    更新后建议执行一次最小可用性验证：使用测试账号登录、打开设备与资产、查看一条识别结果、调用一个已授权 API。验证失败时记录版本号和日志编号，不要重复点击更新。

    常见问题

    看不到系统管理菜单

    当前账号可能不是管理员，或未被授予系统管理相关权限。请联系管理员确认账号角色和权限。

    修改权限后仍然无法访问

    退出当前账号并重新登录；如果问题仍存在，请在日志管理中检查权限变更记录，并确认角色已绑定到正确用户。

    总览页面显示异常

    先刷新页面并确认网络连接，再查看日志管理中的错误记录。若平台版本刚更新，确认更新任务已完成后再重试。
